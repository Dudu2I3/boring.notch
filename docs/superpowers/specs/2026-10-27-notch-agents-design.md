# Челка с агентами Claude Code: дизайн

Дата: 2026-10-27
Машина: личный MacBook Air M2, macOS 15.8.1

## Цель

Одно notch-приложение вместо NotchNook, которое:

- показывает Now Playing (Spotify) с обложкой, переключением треков и визуализатором;
- держит полку: файлы перетаскиваются в челку и обратно;
- показывает статус всех агентов Claude Code (терминал, VS Code, вкладка Code в десктоп-приложении): кто работает, кто ждёт меня, кто закончил;
- по клику на агента переводит в его окно.

Это пет-проект: важны и результат, и опыт работы со Swift через Claude Code.

## Не делаем в первой версии

- Allow/Deny из челки. Челка только сообщает, что агент ждёт; отвечаю в окне агента.
- Сетевые запросы, чтение Связки ключей и токенов, разбор транскриптов, счётчики токенов и стоимости.
- Telegram, лог в Obsidian, поддержка Codex.
- AirDrop, календарь, HUD, зеркало и прочие виджеты: не используются. Если они есть в Boring Notch, их не трогаем.

## Основа

Форк [Boring Notch](https://github.com/TheBoredTeam/boring.notch) (GPL v3). Его код проверен 2026-10-27: телеметрии нет, сеть только для текстов песен (`lrclib.net`) и обновлений.

Гигиена форка:

- Собираю сам из конкретного коммита upstream.
- Подписываю бесплатным сертификатом Apple ID (Xcode → Personal Team). Иначе macOS сбрасывает права «Универсальный доступ» и «Автоматизация» после каждой пересборки.
- Автообновление Sparkle выключено, иначе оно заменит форк оригиналом.
- Весь свой код лежит в `Features/Agents`. Правки upstream-файлов сведены к точкам подключения: регистрация вкладки, правое крыло свёрнутой челки, запуск сервиса. Upstream подтягиваю периодически, потому что Now Playing держится на приватном API Apple и может ломаться с обновлениями macOS.

Rutmehta/Atoll и Notchi не ставим и код из них не копируем. Их можно читать как образец.

## Архитектура модуля `Features/Agents`

```
Claude Code ──hook──► agent-hook.sh ──JSON-строка──► agents.sock ──► AgentSocketServer
                                                                      │
                                                                      ▼
                                                               AgentSessionStore ──► UI (крыло + вкладка)
                                                                      │
                                                                      ▼
                                                               AgentWindowJumper (по клику)
```

Связь односторонняя: приложение только слушает и никогда ничего не отправляет агенту.

### 1. Hook-скрипт `agent-hook.sh`

- Bash, 15–25 строк, без Python и внешних зависимостей.
- Если сокета нет, сразу `exit 0`.
- Читает JSON события из stdin и добавляет поля окружения: `TERM_PROGRAM`, `ITERM_SESSION_ID`, `CLAUDE_CODE_ENTRYPOINT` (если есть), tty и PID родительского процесса.
- Отправляет одну строку через `nc -U -w 1` и выходит. Ничего не печатает в stdout и всегда завершается с кодом 0, поэтому на работу агента не влияет.
- Подписан на события: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Notification`, `PermissionRequest`, `Stop`, `SessionEnd`.

### 2. Установка hooks

- Boring Notch работает в песочнице macOS и не может писать в `~/.claude`. Поэтому hooks ставит отдельная консольная команда из того же репозитория: `swift run --package-path AgentsKit notch-agents-hooks install` (и `uninstall`, `status`). Приложение к `settings.json` не прикасается.
- Перед изменением `~/.claude/settings.json` делается копия с датой в имени.
- Записи добавляются рядом с существующими, ничего не затирается. Свои записи помечены маркером в пути к скрипту, поэтому удаление убирает только их.
- Старые hooks с `terminal-notifier` выключаю вручную после проверки, иначе уведомления будут дублироваться.
- Hooks подхватываются только новыми сессиями Claude Code.

### 3. Сокет `AgentSocketServer`

- Путь: `~/.notch-agents/agents.sock`, права `0600`, папка `0700`. Там же лежит hook-скрипт. Песочнице приложения доступ к этой папке выдаётся точечным исключением в entitlements (`temporary-exception.files.home-relative-path.read-write`). Папка контейнера приложения не подходит: путь длиннее лимита Unix-сокетов в 104 символа, а macOS 14+ спрашивает разрешение у каждого терминала, который туда обращается.
- Каждое подключение — одна JSON-строка. Некорректные строки молча отбрасываются. Строки длиннее 64 КБ обрезаются.
- При старте приложение удаляет оставшийся от прошлого запуска файл сокета.

### 4. Хранилище `AgentSessionStore`

Одна запись на `session_id`: проект (имя папки `cwd`), `cwd`, источник (iTerm, Ghostty, Terminal, VS Code, Claude, другое), статус, текущее действие, последнее сообщение, время начала текущего статуса, данные для перехода (PID, tty, `ITERM_SESSION_ID`).

Статусы и переходы:

| Событие | Новый статус | Что ещё меняется |
|---|---|---|
| `SessionStart` | `idle` (не показывается) | создаётся запись |
| `UserPromptSubmit` | `running` | сбрасывается последнее сообщение |
| `PreToolUse` | `running` | действие = инструмент + короткий аргумент (`Bash: npm test`, `Edit README.md`), до 60 символов |
| `PostToolUse` | `running` | — |
| `PermissionRequest`, `Notification` с типом `permission_prompt` | `waiting` | действие = «ждёт разрешения: …»; один раз за переход в `waiting` показывается плашка |
| `Stop` | `done` | последнее сообщение = первые 80 символов `last_assistant_message` |
| `SessionEnd` | — | запись удаляется |

Прочие `Notification` (например, «ждёт ввода») и `SubagentStop` игнорируются.

Уборка: раз в 30 секунд проверяется, жив ли процесс агента (через `sysctl`, потому что `kill(pid, 0)` в песочнице недоступен). Если процесс умер, запись удаляется. Это покрывает закрытый терминал без `SessionEnd`. Запасной вариант на случай, если песочница не даст узнать о процессе: запись удаляется, если от сессии 6 часов не было событий.

Показываются только сессии со статусом `running`, `waiting` или `done`. Порядок: `waiting`, затем `running`, затем `done`; внутри статуса — по времени.

### 5. Переход в окно `AgentWindowJumper`

| Источник | Как переходим |
|---|---|
| iTerm2 | AppleScript: выбрать сессию по `ITERM_SESSION_ID` (точно до вкладки) |
| Terminal.app | AppleScript: найти вкладку по tty |
| Ghostty | вывести приложение вперёд (точный выбор вкладки проверить в M4) |
| VS Code | открыть ссылку `vscode://file/<cwd>`: VS Code переходит к окну этой папки (из песочницы это проще, чем `open -a`) |
| Десктоп Claude | вывести приложение вперёд; сессию в сайдбаре выбираю сам |
| Не определён | системный звуковой сигнал |

Права: «Автоматизация» для iTerm2 и Terminal. Запрашиваются при первом переходе.

Как отличить десктоп Claude: в его сессиях `CLAUDE_CODE_ENTRYPOINT=claude-desktop` (проверено 2026-10-27). PID агента берётся из `CLAUDE_PID`, если она есть, иначе из `$PPID`.

## Интерфейс

### Свёрнутая челка

- Слева всегда обложка, справа всегда визуализатор музыки (поведение Boring Notch не меняется).
- Правее визуализатора — по точке на каждого показываемого агента: синяя работает, жёлтая ждёт, зелёная закончил. Больше 4 точек → первые 4 по порядку + «+N».
- Агентов нет → справа только визуализатор.
- Переход агента в `waiting` → на 5 секунд правое крыло заменяется жёлтой плашкой «<проект> ждёт», затем точка горит жёлтым до ответа.
- Переход в `done` плашку не показывает, точка просто становится зелёной. Зелёная точка исчезает при следующем `UserPromptSubmit` или `SessionEnd`.
- Если музыка не играет, крыло с точками остаётся, а обложка и визуализатор ведут себя как в upstream.

### Раскрытая челка: вкладка «Агенты»

- Третья вкладка рядом с «Музыкой» и «Полкой». Если кто-то ждёт, на кнопке вкладки горит жёлтая точка.
- Если в момент раскрытия есть агент в `waiting`, челка открывается сразу на этой вкладке, иначе ведёт себя как в upstream.
- Строка: точка статуса, проект, текущее действие или последнее сообщение, источник, время в текущем статусе. Строка ждущего агента подсвечена.
- Клик по строке → переход в окно.
- Пустое состояние: «Агентов нет» и, если hook-скрипта нет, команда для установки.
- Вкладки в шапке Boring Notch видны, только когда полка не пуста. Добавляем условие: или есть агенты.

## Ошибки и отказоустойчивость

- Приложение не запущено → hook выходит мгновенно, агенты работают как обычно.
- Приложение зависло → `nc -w 1` ограничивает задержку hook одной секундой.
- Некорректный JSON или неизвестное событие → игнорируется, запись в лог.
- Переход в окно не удался (нет прав, окно закрыто) → вывести приложение вперёд, иначе подсветить строку.
- Приложение перезапущено → список пуст и заполняется по мере новых событий. Восстановление из транскриптов не делаем.

## Тестирование

- Модульные тесты: разбор JSON событий и все переходы статусов в `AgentSessionStore` (включая плашку один раз на переход и уборку мёртвых процессов).
- Интеграционный тест: поднять сокет во временной папке, отправить события скриптом через `nc`, проверить состояние хранилища.
- Ручной чек-лист: по одной сессии в iTerm2, Ghostty, VS Code и десктопе Claude; запрос разрешения; завершение; закрытие терминала без выхода; музыка и полка работают как до изменений.

## Этапы

| Этап | Результат |
|---|---|
| M0 | Форк собран и подписан, автообновление выключено. Пару дней пользуюсь: музыка и полка устраивают. Иначе останавливаемся и пересматриваем основу |
| M1 | Hook, установщик, сокет, хранилище. Список сессий виден во вкладке «Агенты» (пока без оформления) |
| M2 | Точки и плашка в свёрнутой челке |
| M3 | Вкладка «Агенты» |
| M4 | Переход в окно для всех источников |

После M4: Telegram-уведомления, лог в Obsidian, токены и контекст из транскриптов, при желании Allow/Deny (тогда отдельный дизайн безопасности сокета).

## Риски

- Swift и Xcode незнакомы. Снижаем тем, что модуль маленький и изолированный, а этапы короткие.
- Обновление macOS может сломать Now Playing. Решается подтягиванием upstream.
- Формат событий hooks может меняться в новых версиях Claude Code. Разбор терпим к лишним и отсутствующим полям.
- Права на переход в окна приходится выдавать вручную; без стабильной подписи они слетают.
